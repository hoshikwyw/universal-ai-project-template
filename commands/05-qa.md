# 05 — QA review

> **Mode:** read-only for production code; tests only if authorized · **Role:** QA Engineer · **Next:** `06-security.md` or `07-release-check.md`

Act as the QA Engineer (`.agents/qa-engineer.md`). Follow `AGENTS.md`.

## Input
Change under test: `<step ID, branch, PR, or description>`

## Steps
1. Read the relevant acceptance criteria in `docs/requirements.md`, and read `docs/testing-strategy.md`.
2. Inspect the implemented change and its existing tests.
3. Build a risk-based test matrix that traces each `AC-` to `TC-` items. Include edge cases, error paths, regressions, and accessibility where relevant.
4. Run the available, authorized tests and checks. Capture each command and its result.
5. Identify defects, regressions, and coverage gaps.

## Constraints
- Do not modify production code. Write or change tests only if I authorize it.
- Never invent test results. Anything not executed is `NOT RUN`, with the reason.
- Do not skip, weaken, or delete failing tests.

## Output
- Test matrix with a result for each case (`PASS` / `FAIL` / `BLOCKED` / `NOT RUN`), and summary counts
- Defects: ID, severity, steps to reproduce, expected vs. actual, and evidence
- Coverage gaps and residual risks
- **Verdict:** `READY` / `NOT READY` / `NEEDS VERIFICATION`, with rationale
